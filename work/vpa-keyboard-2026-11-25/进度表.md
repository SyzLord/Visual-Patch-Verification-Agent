## 规则与预算

搜索先做冒烟，再跑 BM25 的第一项。只有这两项都通过，并且原始标题明确提到键盘、方向键、Tab、Enter 等键盘用语，且键盘动作原本排不到 BM25 前两项时，才用键盘动作占最后一步。项目保留相同的 BM25 打分、菜单和稳定排序。规则只接收公开标题和动作说明，因此可以在执行之前输出完整计划。任何已命中的第 2 步都保留。发生提升时，BM25 第二项会被挤出当前三步预算，因此第三步覆盖仍需实测。计划同时记录触发词、原有分数和被替换的动作。[规则代码](route.cjs) · [冻结协议](protocol.json) · [校验值](strategy.sha256)

旧工单 #2266、#2058、#594 的回放仍在第 2 步命中。#1724 的公开标题包含 key up/down，重新规划后，使用上轮完整验收读数可推导出第 3 步命中。四张旧工单用于开发，#594 的两种容器按一个工单计。这一回放没有重开浏览器。[开发集逐单计划](development.json)

- **#1661**。启用日期时间及 altInput，用 Tab 从前一个输入框进入控件，再用方向键和 Enter 把日期从 15 日改到 16 日。继续 Tab，修复版到达下一个输入框，旧版经过页面 body 后回到前一个输入框，复核一致。首次验收的起点只允许焦点落在替代输入框，旧版此时已在日历内。正式复验把起点修正为已进入打开的控件，两个版本都必须完成选日。保留首次快照、原判据和拒绝记录，最终判定仍使用上游描述的 Tab 焦点顺序。[首次验收](flatpickr-1661-attempt/acceptance.json) · [起点修订](fixture-correction.md) · [正式验收](official-1661-b/acceptance.json) · [上游工单](https://github.com/flatpickr/flatpickr/issues/1661) · [修复 PR](https://github.com/flatpickr/flatpickr/pull/1663)

## 解压复跑

在解压根目录执行以下命令。离线入口需要 Python 3.9+ 和 Node.js 18+，现场入口还需要 Chrome 与 Playwright。可用 `VPA_NODE` 和 `PLAYWRIGHT_PATH` 指定本机安装。复现包包含已锁定的四个 npm 归档及实验所需的原始菜单。每条现场命令写入一个新目录。

```sh
cd work/vpa-keyboard-2026-11-25
python3 reproduce.py offline
python3 reproduce.py live 2376 ./run-2376
python3 reproduce.py live 1661 ./run-1661
```

运行 `node route.cjs example-request.json` 可单独输出 #2376 的动作规划。请求包含 `title` 和 `menu`。菜单元素使用 `id` 和 `description`，首项为 `ordinary`，沿用本项目日期菜单中的 `keys`。[可直接运行的请求](example-request.json) · [正式运行输入](official-2376-a/inputs.json)

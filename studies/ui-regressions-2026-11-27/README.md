## 筛选与版本依据

冻结协议沿用旧的标题来源和动作描述。按往轮排序失效的场景补一张会改变搜索顺序的工单，从发布说明补一张普通功能工单，再按历史队列轮取其他组件的两张。各单冻结公开标题、官方 npm 版本、资源哈希、动作、检查点和预期旧版特征后才打开浏览器。此前在标题库见过的记录仍可入组，因为这里检验的是此前未实跑、未用于拟合的工单。以工单计数，Air Datepicker #642 是 #654 的同一故障，只计一次。[冻结协议](protocol.json) · [筛选账本](screening-ledger.json) · [版本及修复来源](cases.json)

- #1943 用报告的 4.6.1 和上游评论实测修复的 4.6.13。两个包都加载各自的官方 rangePlugin。[上游版本对](https://github.com/flatpickr/flatpickr/issues/1943#issuecomment-1593744363)
- #2342 按上游场景从空白仅时间选择器输入 16。发布说明列出该修复，使用 4.6.9。[修复](https://github.com/flatpickr/flatpickr/commit/479418a7a13d987d4a306f7efe3242c3d823c48a)
- #654 用原报告的 3.5.3 和修复提交后的首个可用稳定 npm 版本 3.6.0。#631 的维护者提到 3.5.4，npm 对该版本返回 404，经发布记录核查后使用 3.6.0。两单共享版本对，触发方式和上游修复不同。[范围清除修复](https://github.com/t1m0n/air-datepicker/commit/8496abb1c9bc9258295ce0356a7a616b3cda6b9b) · [隐藏时的键盘修复](https://github.com/t1m0n/air-datepicker/commit/3692ca46293fe6149ebef5e5221e0607aed7ed59)

Air Datepicker 适配器保留同一菜单。手输控制查看输入内容和内部日期各自的状态。#631 单独登记初始焦点、关闭状态和一次 TypeError 的已知失败判据。错误的名称、消息和堆栈随证据保存，其他页面错误仍使运行无结论。此次没有新增能检验「被补位动作挤掉的原动作本来会命中」的真实反例，测试里的替换负例使用合成读数，不计入四张工单。这批结果说明冻结规则在一个新工单上带来额外覆盖，适用范围仍受组件和给定操作菜单限制。

## 复跑

在解压目录使用 Node.js 20+ 和 Python 3.9+。离线验收读取归档，没有浏览器依赖。现场复跑需要安装本机 Chrome 和锁定的 Playwright，发布包、页面与依赖锁都随包提供。

```sh
python3 replay.py offline
node --test test/contract.test.cjs
npm ci --ignore-scripts
python3 replay.py live 1943 ./trial-1943
python3 replay.py live all ./trial-all
```

Windows PowerShell 将 `python3` 换为 `py -3`，将 `npm` 换为 `npm.cmd`。现场入口为每单确认 CLI 退出码 1（已复现已知回归），校验证据后生成新目录内的 `index.html`。其他可单独运行的工单号为 2342、654、631。完整 npm 包的摘要与提取样例资源在锁文件中。离线验收独立重算 JSON 断言、确认条件、三步预算、命中和成本，核对图片与文件摘要。 [版本锁](packages.lock.json) · [最小移植清单](porting.md)
